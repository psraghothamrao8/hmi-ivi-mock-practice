4. Defects, Reports & Test Cases

A. Common HMI / IVI defects (know at least 40 of these)

Use this as your "eye test memory list". When you look at any screen, run through these groups.

Display / visual (UI)

  • Spelling mistake or wrong grammar
  • Text cut off, overlapping, or running outside its box
  • Wrong font size / colour; low contrast (hard to read)
  • Misaligned items; uneven spacing
  • Missing, blurry, stretched or wrong icon
  • Broken image / missing album art
  • Icon and text disagree (toggle looks ON, text says OFF)
  • Screen flickers or tears while changing
  • Day/Night theme wrong: black text on dark background
  • Elements go off-screen in a different language

Cluster / safety

  • Wrong speed (value, or km/h vs mph)
  • Warning lamp not lit when it should be (door, seatbelt, low fuel, engine) – very serious
  • Warning lamp stays lit after the cause is gone
  • Turn signal arrow wrong side / not blinking / wrong blink speed
  • Gear shown wrong
  • Two gears highlighted
  • Warnings not shown in the right order or hidden by another pop-up
  • Cluster slow to react to a speed change (lag)

Function / logic

  • Button does nothing, or does something else
  • Value goes beyond min or max (volume 31, temperature 14)
  • Previous/next track wrong; wrap-around missing
  • Time or date format wrong (0:75, 31/02, 13:00 PM)
  • State not remembered after restart (volume, last source, last language)
  • Settings do not apply
  • Switching units doesn't convert the number
  • Sort order wrong; duplicates in lists
  • Wrong ETA, distance, or route

Connectivity (Bluetooth / phone)

  • Pairing fails or takes too long
  • Shows "Connected" when it is not
  • Contacts do not sync or have garbled characters
  • Call audio on wrong speaker
  • Music does not pause for an incoming call, or does not resume after
  • Wrong caller name
  • Auto-reconnect fails after ignition cycle

State, timing and stability

  • App crash, freeze, "App not responding"
  • Slow start, long black screen after ignition ON
  • Screen stays on after ignition OFF
  • Rear camera late, missing, or only works once
  • Rapid taps cause crash (monkey/stress testing)
  • Memory/CPU high; system slows after hours (soak test)
  • Interrupt handling: call + navigation prompt + reverse at same time

Safety rules (driver distraction)

  • Typing/keyboard not locked while driving
  • Video playing in the front screen while driving
  • Too many pop-ups while driving

Language / region

  • Untranslated words
  • Wrong translation or wrong gender/word
  • German/Finnish long words get cut
  • Right-to-left languages (Arabic) layout not mirrored
  • Wrong units for region (miles in India)

B. A good defect report (template)

Title:        [Cluster] Door-open icon disappears when speed > 5 km/h
Build/SW:     Build 0.9, HMI v2.3.1, Vehicle: Test bench 2
Environment:  Signal simulator + IVI on bench, Android 12
Severity:     Critical   Priority: High (suggested)
Reproducible: 5 out of 5 attempts

Preconditions: Ignition ON, gear D.

Steps to reproduce:
1. Set driver door signal = OPEN.
2. Observe door icon is shown on the cluster (OK).
3. Increase speed signal from 0 to 10 km/h.

Expected: Door-open icon stays ON while the door is open (Req R5).
Actual:   Icon disappears when speed goes above 5 km/h.

Impact:   Driver may not know the door is open while driving → safety risk.
Evidence: video door_icon.mp4, screenshot, logcat_1032.txt (error at 10:32:14),
          CAN trace: DoorStatus 0x350=01 still sent (so signal is OK;
          problem is in HMI logic).
Notes:    Works correctly in build 1.0 earlier. Regression?
Checklist: One bug per ticket · Clear title (where + what) · Exact steps anyone can follow · Expected vs actual · Build number · How often · Logs/video/screenshots · Impact · Don't blame people.
Impact analysis (JD word) = "if this goes to customers, what happens?" Think: safety? legal? user annoyed? brand? how many users? is there a workaround?

Test design tricks: Boundary value – test at the limit and one step either side (14, 15, 16, 17). Equivalence – you don't need to test every number; one from each group (valid, too low, too high). State change – ON/OFF, connected/disconnected. Error guessing – use experience: "what would a developer forget?"

D. Quick practice – write this yourself

Open the Mock Car (Build 0.9), find "Navigation ETA earlier than clock" and write a full defect in the template above. Then compare with this answer:

Show model answer
Title: [Navigation] ETA is earlier than current time for a 25-min route
Build: 0.9   Severity: Major   Priority: Medium   Reproducible: 5/5
Steps: 1. Ignition ON. 2. Open Navigation. 3. Type "Airport". 4. Press Start.
Expected: ETA = current time + 25 min (clock 3:30 PM → ETA 3:55 PM).
Actual: ETA shows 15:05 PM (clock minus 25 min) – also in 24h format with PM.
Impact: Driver gets wrong arrival time; loses trust in navigation.
Evidence: screenshot + video; log line "start nav" at the time.
