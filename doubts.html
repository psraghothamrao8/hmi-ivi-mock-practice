The 15 facts you must know by heart

  1. HMI = everything the driver sees/touches. IVI = the centre screen (infotainment).
  2. Data path: ECU → CAN → Gateway → IVI → Android → HMI screen.
  3. A CAN message = ID + up to 8 data bytes. The DBC file explains the bytes. Lower ID = higher priority.
  4. CAN = main network, LIN = slow/simple (switches), Ethernet = big data (cameras).
  5. Signal simulation = a tool (like CANoe) pretends to be the car so we test on a bench → this is HIL.
  6. V-model: left = define/build, right = test. HMI testers mostly do system + integration testing.
  7. Severity = how bad. Priority = how soon. Example: logo typo = low severity, high priority.
  8. Defect = title, build, steps, expected vs actual, frequency, severity, impact, logs + video.
  9. Automation failure → check environment → script → product bug → flaky? before raising a defect.
  10. ADB: adb devices, adb logcat -c, adb logcat -v time > log.txt, adb bugreport.
  11. Bluetooth: HFP calls, A2DP music, AVRCP controls, PBAP contacts, MAP SMS.
  12. Telltale colours: red danger, amber warning, green on, blue high beam. Bulb check at start is normal.
  13. ISO 26262 = safety, ASIL A–D (D highest). ASPICE = process + traceability.
  14. UDS: 0x22 read version, 0x19 read DTCs, 0x14 clear DTCs. DTC letters: P, C, B, U = network.
  15. Driver distraction: typing/video must be locked while driving – breaking this is a safety defect.

How to handle a question you've never heard

1️⃣ Stay calm and repeat the question in your own words (this gives you thinking time).
2️⃣ Connect it to something you know: "In my internship, I saw something similar when…"
3️⃣ If you really don't know: "I haven't worked with that yet. My understanding is … and I'd learn it by …"
